# ADR-0004: egress はルートのない subnet + 明示的なプロキシで統制し、クレデンシャルはゲートウェイで付ける

- 状態: Accepted
- 日付: 2026-11-06
- 関連: 要件 D4・D9・FR-SEC-03/04 / 設計 §6

## 背景
エージェントは確認なしでコマンドを実行する（D3）。プロンプトインジェクションによる情報の持ち出しや、クレデンシャルの窃取を、エージェントの振る舞いに頼らずに防ぎたい。

## 決定
- ステージ VM の通信は、LNC で **0.0.0.0/0 へのルートがない subnet** に出す。SG で許可する宛先は、egress プロキシ・Git ゲートウェイ・VPC エンドポイントだけにする
- egress プロキシは明示的な forward proxy（CONNECT）とし、**TLS は終端しない**。vmToken でステージを識別し、ネットワークプロファイルの allowlist で判定する
- GitHub への通信は Git ゲートウェイ（リバースプロキシ）を通し、**ユーザーの GitHub トークンはゲートウェイが付ける**。`refs/heads/factory/*` 以外への push は拒否する
- PR の作成など GitHub API の操作は、コントロールプレーンが行う

## 検討した選択肢
- AWS Network Firewall のドメインフィルタ: ステージごとのプロファイルや、クレデンシャルの付与ができない
- TLS を終端するプロキシ（MITM）: VM に独自の CA を入れる必要があり、運用とリスクが増える

## 結果
- 良くなること: プロキシに不具合があっても、ルートがないので「閉じる」側に倒れる。VM の中に価値の高いクレデンシャルがない
- 悪くなること: プロキシを常時動かす必要がある（Fargate）。プロキシの設定に従わないツールは外に出られない（意図どおりの挙動）
