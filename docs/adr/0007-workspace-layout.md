# ADR-0007: 画面はホームの一覧とワークスペース（パターン B）の2層にする

- 状態: Proposed
- 日付: 2026-11-07
- 関連: 要件 D1・D5・FR-UI-01〜09 / [UI 仕様](../06_ui_spec.md) / UI モック（`ui-mock/`、パターン A〜C）
- 一部の置き換え: 依頼の一覧の置き場所と、ワークスペースからの切り替えは [ADR-0010](./0010-session-sidebar.md) で置き換えた

## 背景
UI モックで3つのパターン（A: 会話が主、B: 会話と成果物を左右に並べるワークスペース、C: 一覧と詳細）を作り、**B を採用した**（D20）。ただし B のモックは「1件の依頼を開いた画面」だけで、次のことが決まっていなかった。

1. 依頼の一覧（FR-UI-02）をどこに置くか
2. 右の列のタブの構成（ファイルツリー FR-UI-05 と添付 FR-UI-03 の置き場所）と、タブが自動で切り替わる規則
3. 承認（計画・再承認）とブロックされた通信を、どこに出すか
4. 狭い画面でどうするか
5. 画面は1種類（D5）のまま、LoB の人が研修なしで使えるか（M4 の完了条件）

## 決定
- **ホーム（`/`）は C の表を一覧にし、行を開くと B のワークスペース（`/w/:id`）に入る。** ホームには新しい依頼の入力欄と、「対応が必要な項目」（承認待ちの受け箱）も置く。ワークスペースのヘッダーから、ほかの依頼に切り替えられるようにする
- **右の列のタブは「プレビュー・変更・ファイル・計画・実行ログ」の5つ**にする。添付は、会話の入力欄から上げて、ファイルのタブの `attachments/` で見る
- **タブは状態に合わせて自動で切り替える。ただし、ユーザーが自分でタブを選んだ後は切り替えず、切り替わるはずだったタブに印（点）を付ける**（細かい規則は UI 仕様 §3）
- **承認は会話の中にカードとして出し、計画のタブにも同じカードを出す。** ブロックされた通信は、会話に1行で出し、実行ログのタブにまとめて出す。どちらもホームの受け箱に出す
- **1024px 未満では「会話｜成果物」の切り替えで、どちらか一方を画面いっぱいに出す**（当初は右の列を重ねて開く形にしていたが、ヘッダーの高さを決め打ちした位置合わせが崩れやすく、スマホでは会話の高さも足りなかったため、切り替えに改めた。細かい規則は UI 仕様 §6）
- LoB への配慮: 計画のカードは「人向けの要約」（`summaryForHumans`）を先頭に大きく出し、手順の細部は畳んでおく。会話の中の作業は、ステージごとに1行のまとめにして、ツールの呼び出しの細部は実行ログのタブにだけ出す。完了したら、会話の中に「成果物」のカード（プレビュー・PR・社内公開・ダウンロード）を出す

## 検討した選択肢
| 一覧の置き場所 | 良い点 | 悪い点 |
|---|---|---|
| **C の表をホームにする（採用）** | 複数の依頼の状態・費用・ラインの進み具合を一度に見られる。承認待ちを集められる | ワークスペースとの行き来が1回増える |
| B の左に折りたためるサイドバーを足す | 切り替えが速い | 会話と成果物の2列に3列目が加わり、1280px 前後で窮屈になる |
| パンくずのドロップダウンだけで切り替える | 画面が増えない | 一覧として眺められない（FR-UI-02 を満たしにくい） |

## 結果
- 良くなること: 一覧（全体を見る）と作業（1件に集中する）の役割が分かれる。承認待ちを見落としにくい
- 悪くなること: 画面が2層になる。自動で切り替わるタブの規則は、パイロット（M4）で LoB の人に触ってもらって見直す必要がある
