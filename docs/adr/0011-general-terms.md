# ADR-0011: 画面とコードの言葉を、エージェントのチャットアプリで一般的な名前にそろえる

- 状態: Proposed
- 日付: 2026-11-07
- 関連: [UI 仕様](../06_ui_spec.md) §4 / [API 仕様](../05_api_spec.md) / 要件 FR-LINE

## 背景
画面とコードに「依頼」「ライン」「工程・ステージ」「納品」といった工場の言葉を使っていた。初めて触る人には意味が伝わりにくく、コードの名前（`WorkItem`・`Line`・`Stage`）とも画面の言葉がずれていた。

## 決定
画面・コード・YAML・API の名前を、次のようにそろえる。

| 以前 | 画面 | コード・YAML・API |
|---|---|---|
| 依頼（ワークアイテム） | タスク | `Task`・`taskId`・`/tasks`・画面のパス `/tasks` と `/t/:id` |
| ライン（ファクトリーライン） | ワークフロー | `Workflow`・`WorkflowDefinition`・`workflowRef`・`/workflows`・`/admin/workflows/{name}` |
| 工程・ステージ | ステップ | `StepDef`・`StepRun`・`stepId`・YAML の `steps:`・`/tasks/{id}/steps`・イベント `step.changed` |
| 納品 | 完了 | ステップの ID `deliver` は変えない |
| 依頼者 | 作成者 | — |
| イベント `workitem.state` | — | `task.state` |

- 動詞の「修正を依頼する」（計画への修正の依頼）は、そのまま残す
- YAML のステップの ID（`workbench`・`deliver` など）は利用者が書く値なので変えない
- 要件の ID（`FR-LINE-xx`）、ADR のファイル名、`docs/samples/` の参考コードは変えない（参照が切れないようにする）

## 検討した選択肢
| 案 | 良い点 | 悪い点 |
|---|---|---|
| **画面・コード・YAML をまとめて変える（採用）** | 言葉が1つになり、画面とコードの対応を覚えなくてよい | 変更が大きい。古い YAML（`stages:`）はそのままでは読めない |
| 画面の言葉だけ変える | 変更が小さい | 画面とコードで名前がずれ続ける |
| 「依頼」を「チャット」にする | 会話が中心の見せ方になる | 計画の承認や成果物を持つ単位であることが伝わりにくい |

## 結果（良くなること・悪くなること）
- 良くなること: 一般的なエージェントのアプリと同じ言葉で説明できる。画面の言葉とコードの名前が対応する
- 悪くなること: 登録済みの YAML は `stages:` を `steps:` に書き換える必要がある。API のパスが変わる（まだモックだけなので影響はない）
