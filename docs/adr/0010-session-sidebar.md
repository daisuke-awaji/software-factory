# ADR-0010: タスクの一覧を、折りたためる左のサイドパネルに移す

- 状態: Proposed
- 日付: 2026-11-07（左上のロゴで開くこと・過去のタスクの一覧を、同じ日に追記）
- 関連: 要件 FR-UI-01・02・08 / [UI 仕様](../06_ui_spec.md) §1・§6 / [ADR-0007](./0007-workspace-layout.md)（一覧の置き場所を置き換える）

## 背景
ADR-0007 では、タスクの一覧をホームの表にし、ワークスペースからはヘッダーのドロップダウンでほかのタスクに切り替える形にした。左に折りたためるサイドバーを足す案は、「会話と成果物の2列に3列目が加わり、1280px 前後で窮屈になる」として採らなかった。

この形には、次の問題がある。

1. 承認待ちや実行中のタスクを気にしながら別のタスクを進めるとき、そのたびにホームへ戻る必要がある
2. ドロップダウンには最近の8件しか出せず、状態も一覧として見られない
3. スマホでは、上部のナビゲーション（右上のメニュー）と、ワークスペースの「戻る」ボタンの2つの入り口がある

## 決定
- **左にサイドパネルを置き、全画面で共通にする。** 中身は、新しいタスク、画面の移動（すべてのタスク・公開物・イメージ・ワークフロー・管理）、タスクの一覧（検索と「対応が必要 → 実行中 → 終わったタスクを日付で分けたもの」。下までスクロールすると続きを読む）、アカウント。上部のナビゲーションはなくす
- **ADR-0007 で心配した 1280px 前後の窮屈さは、幅で出し方を変えて避ける。**
  - 1280px 以上: 広げて横に置く（264px）。畳むとアイコンの列（56px）になり、畳んだかどうかを覚えておく
  - 1280px 未満: いつもアイコンの列にし、広げるときは左から滑り込ませてページに重ねる（ページの幅は変えない）
  - 720px 未満: 列も出さず、上の細いバー（ワークスペースではヘッダー）の左上のロゴで、左から滑り込ませる
- **開くのは左上のロゴにする（ハンバーガーのボタンは使わない）。** [Moca](https://github.com/aws-samples/sample-multi-agent-orchestration-chat-on-agentcore) の `SessionSidebar` と同じく、畳んだ列の左上のロゴを押すと広がり、カーソルを乗せるとサイドパネルのアイコンに変わる。スマホでも同じロゴで開くので、どの幅でも入り口が同じ場所になる。閉じるのは閉じるボタン・Esc・外側・左へのスワイプ。左端からのスワイプで開くことはしない（iOS の「戻る」と重なるため）
- **ワークスペースのヘッダーは、画面の幅ではなくワークスペースの幅（コンテナー クエリー）で出し分ける。** サイドパネルを開け閉めしても、タイトルが潰れないようにする
- ホームは「新しいタスク」の入力欄だけにする（対応が必要な項目はサイドパネルに出す。この7日間の集計は出さない）。状態・ワークフロー・所要・費用を見比べる表は「すべてのタスク」（`/tasks`）に移す
- ワークスペースのヘッダーの「ほかのタスクに切り替える」ドロップダウンはなくす（サイドパネルで切り替える）

## 検討した選択肢
| 案 | 良い点 | 悪い点 |
|---|---|---|
| **サイドパネル + 幅で出し方を変える（採用）** | どの画面からでもタスクを切り替えられる。承認待ちが常に見える | 1280px 未満では一覧を見るのに1回押す必要がある |
| サイドパネルをいつも横に置く | 一覧がいつも見える | 1024〜1279px で会話と成果物が窮屈になる（ADR-0007 の懸念のまま） |
| ホームの表のままにし、ドロップダウンを強くする | 画面の作りを変えなくてよい | 一覧として眺められない。ホームへの行き来が残る |

## 結果
- 良くなること: タスクの切り替えが1回で済む。承認待ちの件数がどの画面でも見える。スマホでも入り口が1つになる
- 悪くなること: 表で見比べるには「すべてのタスク」へ移る必要がある。サイドパネルの一覧の読み込み（20秒ごととイベント）が、ホームやすべてのタスクの読み込みと重なる。ロゴがホームへのリンクではなくなる（ホームへは「新しいタスク」か、広げたときのロゴと名前で移る）
