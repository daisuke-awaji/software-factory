# ADR-0009: MSW のモックに、ワークフローの実行を流すシミュレーターを持たせる

- 状態: Proposed
- 日付: 2026-11-07
- 関連: ADR-0002（契約は Zod、フロントエンドは MSW で先に作る）/ 実装計画 §4・§6.3・§7

## 背景
ADR-0002 で「フロントエンドは MSW で先に作る」と決めた。雛形（`docs/samples/src/web/mocks.ts`）のハンドラーは固定の応答を返すだけで、計画の承認、ステップの進行、検証の失敗と戻り、再承認、中断、やり直しといった**時間とともに状態が変わる流れ**を画面で確かめられなかった。

## 決定
- MSW のハンドラーの裏に、**インメモリの DB と、ワークフローの実行を流すシミュレーター**を置く（`packages/web/src/mocks/`）
  - シミュレーターは「台本」（`SimStep` の列）を時間をかけて流し、契約どおりのイベント（`FactoryEvent`）を出す。タスクの内容からシナリオ（Web フォーム、ダッシュボード、README、表記ゆれ、レポートなど）を選ぶ
  - ワークフローの定義（YAML → `Workflow`）どおりに次のステップに進む。`on.fail.goto` と `maxLoops` も同じように扱う
  - 計画の承認・修正の依頼・却下、再承認、追加の指示、中断、中止、やり直し、VM の強制停止を受け付ける。状態が合わない操作は 409 を返す
- **初期データ（シード）も、シミュレーターを過去の時刻で一気に流して作る。** イベントの履歴、ステップの実行、ファイル、差分が必ず揃う
- ブラウザでは DB を `localStorage` に保存し、再読み込みしても続きから流れる。`?mock-reset` で作り直し、`?mock-speed=5` で速さを変える
- 同じハンドラーを、開発（`setupWorker`）・結合テスト（`setupServer`）・E2E（ブラウザ）で使う。入力も出力も contracts で検証する
- 本物と違う点は、次の3つだけにする（コードにも書く）
  - プレビューの URL: 本物は `https://<Preview>/__open?t=<チケット>`。モックはワークスペースのファイルから組み立てた HTML の Blob URL
  - presigned URL: 本物は S3。モックは `https://files.factory.mock/...` を MSW が受ける
  - GitHub の連携: 本物はページの遷移で認可する。モックは設定の画面からその場で切り替える

## 結果
- 良くなること: バックエンドがなくても、M1〜M4 の画面の流れを最後まで操作できる。E2E で「作成 → 計画 → 承認 → 検証のやり直し → PR → プレビュー → 公開」を確かめられる
- 悪くなること: シミュレーターの台本は保守が要る。本物の挙動（エンジンと agentd）と食い違ったら、契約のテストで気づけるように、イベントの形は contracts だけで決める
