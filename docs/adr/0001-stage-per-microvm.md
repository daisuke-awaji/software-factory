# ADR-0001: 1ステップに1台の Lambda MicroVM を使う

- 状態: Accepted
- 日付: 2026-11-06
- 関連: 要件 D15・FR-ENV・FR-LINE / 設計 §3・§4

## 背景
ファクトリーのステップ（実装、検証、レビューなど）ごとに、必要なツール、ネットワークの許可範囲、権限が違う。エージェントには細かな確認なしで作業させる（D3）ので、作業環境どうしを強く隔離したい。

## 決定
- ステップごとに、そのステップ用のイメージ（`name@version`）から **Lambda MicroVM を1台**起動する。VM はステップの終わりに終了する（`keepVm` を指定した場合を除く）
- 状態は VM の外（DynamoDB / S3 / Git）に置き、ステップ間の受け渡しは明示的に行う
- VM のサイズはイメージで決まる（`RunMicrovm` では指定できない）。サイズ違いは別のイメージにする

## 検討した選択肢
- 1つの VM で全ステップを実行する: 起動が少ないが、ステップごとにツールや権限を変えられず、隔離もできない
- ECS / Fargate のタスク: 起動が遅く（数十秒）、suspend / resume がない
- Lambda 関数: 15分の上限があり、長いセッションや対話に向かない

## 結果
- 良くなること: ステップごとに隔離、ツール、権限、ネットワークを変えられる。snapshot から数秒で起動でき、待っている間は suspend できる
- 悪くなること: 1台あたり8時間の上限があり、チェックポイントからの引き継ぎを実装する必要がある（設計 §3.8）。VM のメモリのクォータ（suspended の VM も数える）を管理する必要がある
