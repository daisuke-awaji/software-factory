## 1. 画面の一覧

| `/tasks` | すべてのタスク | FR-UI-02 | タスクの表（状態・ワークフロー・所要・費用・更新）。絞り込み・検索・アーカイブ |
| `/t/:id` | ワークスペース | FR-UI-01〜07、FR-PLAN、FR-SHARE | 左に会話、右に成果物のタブ、下にステータスバー（§2） |

| `/images` | イメージ | FR-IMG | 使えるイメージ（既定・組織・プロジェクト・自分）。カスタムイメージの作成（定義の YAML を見ながら）、ビルドの進み具合とログ、公開範囲の変更 |
| `/workflows` | ワークフロー | FR-LINE | ステップの並び、VM のイメージ、通信のプロファイル、失敗したときの戻り方 |
| `/admin` | 管理（Admin のみ） | FR-ADM | 通信の許可リスト、パッケージソース、ワークフローの登録（YAML）、VM と容量（強制停止）、ユーザー（ロールと上限）、イメージの組織への公開の承認 |
| `/settings` | 設定 | D11 | GitHub との連携、テーマ。モックのときは、進む速さ・管理者の切り替え・データの作り直し |

左のサイドパネルは全画面で共通（ADR-0010）。ワークスペースだけは、サイドパネルの右を画面の高さいっぱいに使う。

### 1.1 サイドパネル
| 場所 | 内容 |
|---|---|
| 上 | 広げているとき: ロゴと名前（ホームへ）、畳む・閉じるボタン。畳んだ列: **ロゴ**（押すと広げる。カーソルを乗せるとサイドパネルのアイコンに変わる）。どちらも `⌘/Ctrl + B` |
| 移動 | 新しいタスク（`/`）、すべてのタスク（承認待ちの件数のバッジ）、公開物、イメージ、ワークフロー、管理（Admin のみ） |
| タスクの一覧 | 検索と、「対応が必要」→「実行中」→ 終わったタスク（**今日・昨日・過去7日間・それより前**。暦の日で分ける）の順の一覧。1件は状態の点・タイトル・更新。開いているタスクは強調する。30件ずつ読み、下までスクロールすると続きを読む（失敗したら「続きを読み込む」で読み直す。検索は読み込んだ分から探し、続きがあれば読み進める）。状態が変わったらイベントで先頭のページを読み直す（20秒ごとにも読み直す） |
| 下 | モック・再接続中の印、アカウント（テーマ・設定） |

- 畳むと、移動とアカウントのアイコンだけの列（56px）になる。タスクの一覧は出さない。畳んだかどうかは `localStorage`（`sf.sidebar`）に残す
- 幅ごとの出し方は §6

## 2. ワークスペース

```
┌ （左にサイドパネル）──────────────────────────────────────────────────┐
│ タスク › acme/support-site › factory/xxxx › タイトル [状態]  ●計画─●実装─○検証… [PR #128] … │
├──────────────── 会話 ────────────────┬──────── 成果物 ────────────────┤
│ タスクの本文（添付）                     │ [プレビュー|変更 3|ファイル|計画|実行ログ] │
│ エージェントの発言（ストリーミング）     │                                  │
│ 計画のカード（承認・修正の依頼・却下）   │  タブの中身                        │
│ 作業のまとめ（ステップごとに1行）       │                                  │
│ 再承認のカード / 止めた通信（1行）      │                                  │
│ 成果物のカード / 失敗のカード           │                                  │
│ ┌入力欄（添付・中断・送信）┐            │                                  │
├──────────────────────────────────────┴──────────────────────────────────┤
│ VM 実行中: 実装 · web@5 │ 通信: web（許可リストのみ） │ トークン · 費用          │
└──────────────────────────────────────────────────────────────────────────┘
```

- **ヘッダー**: パンくず（タスク › リポジトリ › 作業ブランチ › タイトル。幅が足りないときはリポジトリとブランチから縮め、ワークスペースの幅が 900px 未満ならタイトルだけにする）、状態のタグ（再承認のときは「外部への通信の承認待ち」のように理由を出す）、ワークフローの進み具合、PR、その他の操作（名前の変更、アーカイブ、作業の中断、ワークフロー全体の中止）
- **会話**: イベントを畳み込んだタイムラインを出す（`lib/session.ts`）。続けて動いたツールは1つの「作業のまとめ」にし、ステップの実行ごとに1行で、いま動いているツールの説明か、最後の結果を出す。細部は「ログ」から実行ログのタブで見る
- **入力欄**: 状態で文言と動きが変わる。計画の承認待ちのときに送ると「修正の依頼」になる。実行中は「中断」を出す。中断中に送ると続きから再開する。`⌘/Ctrl + Enter` で送る（Enter は改行。日本語の変換の確定と衝突させない）
- **ステータスバー**: いま動いている VM（ステップ・イメージ）、通信のプロファイル、止めた通信の件数、トークンと費用、WebSocket の接続状態（つながっていないときだけ）。VM が止まった後の「すべて停止しました（台数・合計時間）」や経過時間は出さない

## 3. 右の列のタブ

| タブ | 中身 | 空のとき |
|---|---|---|
| プレビュー | VM の中で待ち受けているアプリを iframe で開く。再読み込み、新しいタブで開く（どちらもチケットを発行し直す） | 「エージェントがアプリを起動すると、ここに表示されます」 |
| 変更 | 作業ブランチの差分（ファイルの一覧と unified diff） | 「まだ変更はありません」 |
| ファイル | ワークスペースのファイルツリー（実行中は VM、終了後はスナップショット）、中身、ファイル単位と zip のダウンロード、公開 | 「ファイルを選んでください」 |
| 計画 | 最新の計画のカード（承認できる）、ワークフローのステップの構成、前の版 | 「計画を立てています」 |
| 実行ログ | 使用量、止めた通信、ステップの実行ごとのツールの呼び出し（AffectUI の Tool Call Group / Card）、失敗したステップのやり直し | 「計画が承認されると、ここに出ます」 |

### 3.1 自動で切り替わる規則
| 状態 | 開くタブ |
|---|---|
| 受付済み・計画中 | 計画 |
| 承認待ち（計画） | 計画 |
| 承認待ち（再承認） | 実行ログ |
| 実行中・一時停止 | 実行ログ（プレビューが用意できたら、プレビュー） |
| 完了 | プレビュー（なければ変更） |
| 失敗・中止 | 実行ログ |

- **ユーザーが自分でタブを選んだ後は、自動では切り替えない。** 代わりに、切り替わるはずだったタブに点の印を付ける（計画はオレンジ、それ以外は青）。そのタブを開くと印は消える
- ほかのタスクに移ったら、規則は最初からに戻る

## 4. 言葉の約束（FR-UI-09）
| 内部の名前 | 画面の言葉 |
|---|---|
| queued / planning / awaiting_approval / running / suspended / completed / failed / cancelled | 受付済み / 計画中 / 承認待ち / 実行中 / 一時停止 / 完了 / 失敗 / 中止 |
| task / workflow / step（[ADR-0011](./adr/0011-general-terms.md)） | タスク / ワークフロー / ステップ |
| workbench / implement / verify / review / deliver / publish | 作業 / 実装 / 検証 / レビュー / 完了 / 公開の提案 |
| scope / egress / budget / time（再承認の理由） | 作業の範囲の変更 / 外部への通信 / 予算 / 作業時間 |
| エージェント | 会話の中では「ファクトリー」。アイコンは幾何形（AI らしいきらきらは使わない） |

- 時刻は `HH:mm`、一覧の更新は「3分前」「昨日」のように出す。費用は米ドル（`$0.48`）
- エラーは `ApiError.message` をそのまま出す（バックエンドで日本語にする）。401・503・通信の失敗だけは画面の側で言い換える

## 5. 承認と通知の出し方
| 何を | 会話 | 右の列 | サイドパネル |
|---|---|---|---|
| 計画の承認 | 計画のカード（承認して開始・修正を依頼・却下） | 計画のタブに同じカード | 「対応が必要」 |
| 再承認（範囲・通信・予算・時間） | 再承認のカード（許可する・許可しない） | 実行ログのタブに切り替える | 「対応が必要」 |
| 止めた通信 | 1行（ホスト名と時刻） | 実行ログのタブの先頭にまとめる。ステータスバーに件数 | — |
| 完了 | 成果物のカード（プレビュー・PR・社内公開・ダウンロード） | プレビューのタブに切り替える | サイドパネルの状態の点 |
| 失敗 | 失敗のカード（理由・実行ログを見る・やり直す） | 実行ログのタブ | サイドパネルの状態の点 |

- 回答したカードは、だれがいつ回答したかの1行に変わる。古い版の計画は要約だけにして薄く出す
- 同じ承認を2回押しても、2回目はサーバーが 409 を返し、画面はそのメッセージを出す

## 6. 狭い画面とスマホ
スマホでは「**状況を見る・承認する・ひとこと指示する**」を快適にすることを優先する。管理・イメージ・ワークフローの YAML の編集は、崩れずに使えることまでを確かめる。

| 幅 | レイアウト |
|---|---|
| 1280px 以上 | サイドパネルを広げて横に置く（264px。畳むとアイコンの列） |
| 1280px 未満 | サイドパネルはアイコンの列にし、左上のロゴで、**左から滑り込ませて**ページに重ねる（ページの幅は変えない。Esc・外側を押す・左へスワイプ・画面を移ると閉じる。動きを減らす設定では滑らせない） |
| ワークスペースの幅 1100px 以上 | 2列。ヘッダーにワークフローの進み具合を出す（画面の幅ではなく、サイドパネルを除いたワークスペースの幅で決める: コンテナー クエリー） |
| ワークスペースの幅 1100px 未満 | 2列。ワークフローの進み具合は隠す |
| 1024px 未満 | ワークスペースは、ヘッダーの下の「**会話｜成果物**」の切り替えで、どちらか一方を画面いっぱいに出す。会話のカードから成果物のタブを開く操作（「ログ」「開く」など）は、成果物の表示に切り替える。自分でタブを選んだ後の点の印（§3.1）は「成果物」にも付ける |
| 720px 未満 | サイドパネルの列は出さず、上の細いバーの**左上のロゴ**で、左から滑り込ませて出す（ハンバーガーのボタンは使わない）。ワークスペースでは細いバーも出さず、ヘッダーの左上のロゴで開く。左端からのスワイプで開くことはしない（iOS の「戻る」と重なるため）。ワークスペースのヘッダーは「ロゴ・タイトル・状態・その他の操作」だけにし、PR は「その他の操作」から開く。ステータスバーは動いている VM（なければ通信）と接続の状態だけにする。すべてのタスクは表ではなくカード（タイトル・リポジトリ・費用・状態・ワークフローの進み具合・更新）にする。ダイアログは画面の下から出るシートにする |
| 高さ 520px 以下（横向きのスマホ） | 入力欄の説明とステータスバーを隠し、会話に高さを回す。サイドパネルは列を詰め、広げたときは全体をスクロールさせる |

- 幅の値は CSS の `@media` と `lib/useMediaQuery.ts` の `narrow` で揃える。見た目だけの違いは CSS で、出す部品が変わるもの（切り替え、カードの一覧）は `useMediaQuery` で書く
- **タッチの画面**（`pointer: coarse`）では、押せる部品の高さを 40px 以上（`--tap-min`）、入力欄の文字を 16px 以上（`--fs-input-min`。iOS がフォーカスで拡大しないように）にする。AffectUI の部品はファイルを変えず、`global.css` から CSS 変数で上書きする（ADR-0008）。`⌘ / Ctrl + Enter` の案内は出さない
- ノッチとホームバー: `viewport-fit=cover` にし、サイドパネル・上の細いバー・ワークスペースのヘッダー・ステータスバー・ページの余白に `env(safe-area-inset-*)`（`--safe-*`）を足す。画面の高さは `100dvh`（アドレスバーの出入りで変わらないように）
- 確かめ方: Playwright の `iphone`（iPhone 13 の寸法を Chromium で）と `android`（Pixel 7）のプロジェクトで `e2e/mobile.spec.ts` を、デスクトップで `e2e/sidebar.spec.ts`（1440px と 1100px）を動かす。全画面で横スクロールが出ないことも確かめる

## 7. LoB の人への配慮（D1・D5）
- 画面は1種類のまま、**最初に目に入るものを平易にする**: 計画は人向けの要約を先頭に大きく、手順は番号つきの短い文。目的・成果物・完了の条件は畳んでおく（外部への通信が必要なときだけ最初から開く）
- 会話の中のツールの呼び出しは「ステップごとに1行」にまとめ、コマンドや引数は実行ログのタブにだけ出す
- 新しいタスクで選ぶのはリポジトリだけにする。ワークフローは選ばせず、リポジトリを使うなら「作って確かめる」、使わないなら会話にする
- 保護されていないブランチのリポジトリを選ぶと、レビューを必須にするよう警告する（D7）

## 8. アクセシビリティ
- タブは `role="tablist"`（AffectUI の Segmented Control の `kind="tabs"`）。ダイアログは `<dialog>` で、Esc で閉じる
- ストリーミング中の発言は `aria-live="polite"`。状態は色だけでなく文字でも出す（タグ、ワークフローの進み具合の `sr-only` の文言）
- 本文へのスキップリンク。キーボードだけで、タスク → 承認 → 公開までを操作できる
- `prefers-reduced-motion` でアニメーションを止める

## 9. モックで確かめられること
シード（初期データ）には次の5件と、過去のタスクが32件（1〜95日前に終わったもの。うち2件は取り下げ）入っている。`?mock-reset` で作り直せる。

| タスク | 状態 | 確かめられること |
|---|---|---|
| README に開発手順を追記 | 実行中 | ストリーミング、作業のまとめ、自動で切り替わるタブ、中断と再開 |
| 週次売上ダッシュボードを追加 | 計画の承認待ち | 承認・修正の依頼（第2版）・却下。承認すると、外部への通信の再承認が出る |
| 問い合わせフォームの入力チェックを直す | 完了（PR #128） | 検証の失敗と実装への戻り、プレビュー（フォームが動く）、差分、ダウンロード |
| 顧客リストの表記ゆれを統一 | 失敗 | 失敗のカード、やり直し |
| 部署別の売上レポートを作って公開 | 完了・公開済み | 社内公開（公開前のチェック、範囲、期限）、公開物の一覧 |
| 過去のタスク（32件） | 完了・中止 | サイドパネルの日付の分け方（昨日・過去7日間・それより前）と、スクロールでの続きの読み込み（30件ずつ） |
